\section{WebAssembly primer}
When one refers to \textit{WebAssembly} or \textit{Wasm}, one usually means the WebAssembly (core) module standard, originally introduced in~\cite{wasm1.0spec}.
The standard is evolving, the currently standarised version is version 3.0~\cite{wasm3.0spec}.

Commonly advertised features of Wasm are its performance, and security: a Wasm module is a sandbox that can interact with the host only in the
ways that are explicitely permitted; there are no syscalls or the like in Wasm.

In the context of verification, the main benefit is that the specification formally defines Wasm's syntax, the type system (with progress and preservation statements)
and an operational semantics. New feature additions to the standard are mechanized (usually with some delay), and reported mistakes integrated.
WasmCert-Coq is a well-maintained mechanization of the Wasm 2.0 standard, there are also mechanisations in Lean and Isabelle: \todo{links}.

CertiRocq's Wasm backend generates such a Wasm module.

\subsection{Wasm component model}
A more recent addition to the Wasm ecosystem is the Wasm component model \todo{}.
In its simplest form, a Wasm component is a Wasm module wrapped in a cleaner interface, listing the module's imported and exported functions (and no other internals).
The type system is also richer: in addition to Wasm's primitive types (i32, i64, f32, f64\footnote{Since version 3.0, additional heap-allocated arrays and record types.}),
the component's type system has native strings, user-defined records, and option and result types.
For these types, the component model defines the representation in the embedded Wasm core module and lifting operations.

Wasm components with corresponding imports and exports can be composed, leading to a component containing multiple modules. 

Further, using Wasm components allows for straightforward integration with other languages.


I'm not aware of a mechanization of the Wasm component standard, in fact it doesn't yet have a standardised semantics or specification document.

Having one would allow verifying the interaction between Wasm core modules and glue code.

\subsection{Wasm system interface (WASI)}

The current version of the component model is 0.3, calling it \`'widely supported\`' would be an overstatement.
However, it is implemented by \textit{wasmtime}, one of the most popular Wasm runtimes.



Defining such an interface may not seem terribly exciting. However, since it's being standardised, other projects are building tooling and infrastructure on top of it
\cite{wasi.dev}.

that makes it more convenient to deploy and integrate Wasm code in larger software projects.


Today, CertiRocq's Wasm backend~\cite{certicoqwasm-cpp2025} generates a Wasm (core) module. This module exposes a number of internals relevant for writing glue code.
